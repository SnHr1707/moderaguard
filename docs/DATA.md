# Data (owner: M1)

The repository runs out of the box on a **synthetic sample** (`data/sample/`,
generated by `python -m moderaguard.data.make_sample`). For the final results,
use the real datasets below. Neither dataset may be committed to Git; DVC stores
them in the S3 bucket instead.

## 1. Jigsaw Unintended Bias in Toxicity Classification

- Source: Kaggle competition `jigsaw-unintended-bias-in-toxicity-classification`
  (accept the competition rules on Kaggle first).
- File needed: **`all_data.csv`** (about 2 million comments, 2015-09 to 2017-11). It has
  `id`, `comment_text`, `toxicity`, `created_date` and the identity columns used
  for the fairness audit. About a quarter of the rows have identity annotations;
  the rest are empty, which the pipeline treats as "no identity mentioned".
- Licence: CC0 (comments), see the competition page.

```bash
pip install kaggle                    # needs ~/.kaggle/kaggle.json (Kaggle → Account → API token)
kaggle competitions download -c jigsaw-unintended-bias-in-toxicity-classification -f all_data.csv -p data/raw/jigsaw
unzip data/raw/jigsaw/all_data.csv.zip -d data/raw/jigsaw && rm data/raw/jigsaw/all_data.csv.zip
```

`params.yaml` → `data.max_rows` (default 200,000) subsamples it so training stays
fast on a laptop. Comments created on or after `data.drift_split_date`
(2017-06-01) are held back as the stream that causes drift.

## 2. YouTube Spam Collection

- Source: UCI Machine Learning Repository, dataset 380 ("YouTube Spam Collection").
- Files: five CSVs (`Youtube01-Psy.csv` … `Youtube05-Shakira.csv`), 1,956 comments,
  columns `COMMENT_ID, AUTHOR, DATE, CONTENT, CLASS`. Licence: CC BY 4.0.
- Put all five CSVs in `data/raw/youtube_spam/`.

## 3. (Optional) fastText language identification model

- `lid.176.ftz` (917 KB, 176 languages) from the fastText website ("Language
  identification" page). Licence: CC BY-SA 3.0.
- Put it at `data/raw/lid.176.ftz`. Without it, language ID falls back to a
  small stop-word heuristic (English, Spanish, French, German, Hinglish).

## Versioning the data with DVC

```bash
dvc add data/raw/jigsaw data/raw/youtube_spam data/raw/lid.176.ftz
git add data/raw/*.dvc data/raw/.gitignore
git commit -m "data: track Jigsaw, YouTube spam and lid.176 with DVC"

# S3 credentials stay out of Git (.dvc/config.local is git-ignored)
dvc remote modify --local storage access_key_id moderaguard
dvc remote modify --local storage secret_access_key moderaguard-secret
dvc push                              # uploads to s3://dvc on the SeaweedFS server

dvc repro                             # rebuilds processed data, models and reports
git add dvc.lock && git commit -m "pipeline: results on the real data"
```

Teammates then run `dvc pull` to get exactly the same data. Every commit's
`dvc.lock` records which data and parameters produced which models and metrics,
so `git checkout <commit> && dvc checkout` restores any earlier experiment.
To compare runs: `dvc metrics diff` and `dvc params diff`.

## Validation

`python -m moderaguard.data.validate` checks both datasets with Pandera
(schema, value ranges, label balance, empty comments) and writes
`reports/validation.json`. A failure stops `dvc repro`, the Airflow DAGs and
Jenkins, so a bad file never reaches training.
